# FalloutCraft v0.3.5 freeze-guard test

This patch is built from the exact owner-supplied v0.3.4 binary baseline.

## Native freeze fix

v0.3.4 calls the Fallout player `Actor::SetPosition` vfunc at every Fallout render frame after takeover. The v0.3.5 recovery patch replaces that callsite with a small position-independent thunk that gates the actual host actor relocation to at most once every 50 ms (~20 Hz), while leaving the existing per-frame interpolation/camera code in place.

This directly targets the observed failure sequence: mirror world succeeds, takeover succeeds, first `SetPosition` returns, first overlay frame presents, then Fallout stops heartbeating.

## Fabric cleanup

The Fabric metadata is updated to v0.3.5 and the stale startup diagnostic that still said v0.3.3 is corrected.

## Status

Runtime testing is still required. Do not promote v0.3.5 as stable until the freeze is confirmed gone.

The final project target remains the full SkyCraft-class architecture in Fallout: real host collision streaming, world-space Minecraft rendering, real Minecraft third-person avatar/skin/armor rendering, F5 camera parity, entities/particles, lighting, water, NPC combat proxies, destruction, and death/ragdoll behavior.
