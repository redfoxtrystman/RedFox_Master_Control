# FalloutCraft v0.3.8 — NO-GDI architecture isolation test

This build isolates the temporary Fallout-side GDI compositor.

## Why

v0.3.7 still reaches Minecraft takeover and the first HUD frame, then Fallout stops advancing. The final native diagnostics are the temporary GDI overlay worker creating its window and presenting the first Minecraft overlay frame.

Current SkyCraft does not use a separate GDI/layered window. It hooks the host DXGI Present path and draws Minecraft's HUD directly into the host game's Direct3D swap chain. SkyCraft also heartbeats from Present.

## v0.3.8 changes

Starting from the exact v0.3.4 recovery baseline, this reproducible patch applies the existing v0.3.7 safety changes and then:

- keeps Actor::SetPosition reference-only (updateCharController=false);
- keeps the unsafe Fallout look-routing call disabled;
- **completely skips the CreateThread path that starts FalloutCraft's temporary GDI compositor**;
- therefore no GDI overlay window, UpdateLayeredWindow loop, or background overlay worker can run;
- leaves shared-memory IPC, Minecraft takeover, input routing, and player-reference movement active.

The Minecraft HUD is expected to be absent in this isolation build. That is intentional.

## Test interpretation

- **Fallout stays responsive for 30–60+ seconds:** the GDI compositor is the freeze source. Replace it with a DXGI Present-hook compositor modeled on SkyCraft.
- **Fallout still freezes:** GDI is ruled out. Next target is the Fallout task-interface/update execution path; move host mutation into a proper Fallout PlayerCharacter update hook and add P/H/X frame breadcrumbs.
