# FalloutCraft v0.4.0 — Minecraft look ownership test

Observed in v0.3.9: mouse movement became available again, but the view repeatedly snapped back.

Recovered Fabric bytecode showed the exact feedback path: `FalloutClient.beginFrame()` drains Fallout input into Minecraft and then, later in the same frame, overwrites the local player's `YRot`, `XRot`, `yRotO`, and `xRotO` from `HostState.yaw/pitch` every frame.

v0.4.0 removes only those four continuous host-to-Minecraft rotation writes. The initial/load teleport rotation remains intact. The native v0.3.9 mouse/look route remains enabled and the GDI compositor remains disabled.

This is an ownership test: Minecraft is allowed to retain the routed mouse rotation and publish that yaw/pitch back to Fallout instead of immediately being reset by HostState.

Collision is a separate missing subsystem. The recovered Fabric build still contains only the temporary support-floor fallback and no Fallout collision-ring consumer / SkyCollider equivalent, so Vault walls and terrain are not expected to block the Minecraft player yet.
