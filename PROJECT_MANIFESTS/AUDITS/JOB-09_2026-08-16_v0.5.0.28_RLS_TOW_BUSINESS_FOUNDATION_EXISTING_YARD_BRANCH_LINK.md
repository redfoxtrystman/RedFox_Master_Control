## User requirement

Already-created RedFox Tow Yards must be upgradeable in place into branches of one RedFox Tow business, analogous to the existing workflow that links a selected RedFox Tow Yard to a purchased RLS property. Existing yard identity/storage/capacities/location/property links must not be replaced.

## Exact RLS source findings used

### Business Manager
`career/modules/business/businessManager.lua` exposes:
- `registerBusiness(businessType, businessObject)`
- `registerBusinessCallback(businessType, callbacks)`
- `isPurchasedBusiness(businessType, businessId)`
- `showPurchaseBusinessPrompt(businessType, businessId)`

For a facility with `price = 0`, `showPurchaseBusinessPrompt()` calls RLS's own purchase path immediately. RLS then:
- records the purchased business in its own `businesses.json`;
- sets Business Computer context;
- calls `career_modules_bank.createBusinessAccount(...)`;
- invokes the registered `onPurchase` callback;
- saves through the Career save system.

### Bank
`career/modules/bank.lua` exposes:
- `createBusinessAccount`
- `getBusinessAccount`
- `getAccountBalance`
- `getAccountTransactions`

Business account IDs are generated as `business_<businessType>_<businessId>`.

### Business Computer
`career/modules/business/businessComputer.lua` resolves business modules generically as `career_modules_business_<businessType>` and calls that module's `getUIData(businessId)`. It is therefore not limited to only tuningShop/racingTeam for the generic business-computer route.

### Career module loading
RLS's Career override recursively scans `lua/ge/extensions/career/modules/*.lua`, loads the discovered modules, and invokes `onCareerActivated`. A JOB-09 module at `lua/ge/extensions/career/modules/business/redfoxTow.lua` therefore participates in the existing RLS Career module loader without replacing an RLS source file.

### Facility registry limitation
RLS `freeroam_facilities` has a hard-coded facility-type map and does not natively know a `redfoxTow` facility type. JOB-09 does **not** modify that RLS file. The isolated RedFox business module installs a narrow runtime wrapper around `getFacility`/`getFacilitiesByType` that intercepts only `redfoxTow` and delegates every other facility type to the exact function that was present before the wrapper. It restores the original functions on unload when still safe to do so.

## v0.5.0.28 implementation

New isolated module:
`lua/ge/extensions/career/modules/business/redfoxTow.lua`

Business identity:
- type: `redfoxTow`
- ID: `redfox_tow_company`
- name: `RedFox Tow & Recovery`
- one RLS business/account shared by all linked RedFox Tow Yard branches

Existing-yard behavior:
- no replacement yard is created;
- existing yard ID is retained;
- storage key is retained;
- location/rotation retained;
- custody/company/sales capacity retained;
- existing `rlsGarageId` / purchased-property link retained;
- branch membership is additional metadata only;
- first linked yard becomes the dynamic primary business anchor;
- additional existing yards become branches;
- primary anchor can be changed without recreating yards.

## Transaction safety

JOB-09 saves the RedFox branch record **before** invoking RLS's official zero-price business purchase path. If that RedFox save fails, RLS is not touched. If RLS rejects/fails the business creation, JOB-09 restores the prior RedFox foundation/yard snapshot and saves the rollback.

If RLS already reports the business purchased but its business bank account is missing, the bridge uses RLS's public `createBusinessAccount` API to repair that missing account before reporting success.
