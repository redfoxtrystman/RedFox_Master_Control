## User-reported issues reproduced in source

1. Abandoned vehicle Search / Place on Hold / Immediate Salvage controls were rendered after the active-call Queue Another Job controls and after the full RLS Off-Road Recovery board, which made the disposition action look detached from the vehicle it belonged to.
2. `M.rlsRecovery.draw()` was called twice in the active-call renderer, so the native Recovery block could appear twice around the abandoned hold controls.
3. Tow font scale was applied to the parent ImGui window, but the scrolling main content and Settings content are separate ImGui child windows. Button box height is explicitly scaled, so buttons visibly changed while ordinary child-window body text could remain at the prior/default scale.
4. Impound/lien timers still used `os.time()` and 86400-second wall-clock days. This violated the required Career game-day behavior.

## Exact RLS timing finding

RLS 2.7.0.1 `career/modules/propertyRentals.lua` defines `SIM_SECONDS_PER_GAME_DAY = 1200` and advances its persistent rental timing from `dtSim`. JOB-09 v0.5.0.32 adopts the same Career simulation-day basis for impound/lien countdowns and per-day storage billing.

## v0.5.0.32 changes

- Applies Tow local font scaling again immediately after entering the main scrolling child window and the Settings scrolling child window, so ordinary labels, wrapped body text, disabled text, and other child-window text follow the user's Tow Font Scale setting.
- Keeps the existing local F11/global-scale compensation; JOB-09 still does not write BeamNG's global ImGui scale.
- Moves abandoned Search / Hold / Immediate Salvage controls directly beside the active target information and before Queue Another Job / RLS Recovery content.
- Hides route buttons while the abandoned event is already in the final disposition decision phase.
- Removes the second duplicate `M.rlsRecovery.draw()` from the active-call page.
- Introduces a persistent per-Career-save Tow simulation clock advanced by `dtSim`.
- New lien/impound records store `storedAtGameTime` / `eligibleAtGameTime` and use 1200 simulation seconds per Career game day.
- Existing v31-and-older lien records lazily migrate away from real-time countdowns. Because historical game-day elapsed time was not recorded, migrated records start a clean full Career-day hold when first migrated rather than inferring progress from wall-clock time.
- Storage billing days, disposition eligibility, claim storage-day calculations, and the UI hold countdown now use Career game days.
- Wall-clock `storedAt` is retained only as an intake/history timestamp; it is no longer authoritative for lien countdowns.
- Existing RLS Tow business Garage / Finances foundation from v0.5.0.30-v0.5.0.31 is preserved.
